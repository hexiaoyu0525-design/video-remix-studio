# 01 · 立项 BRIEF 与导演案 TREATMENT

本技能所有事实分三处维护：**BRIEF 记用户权威，TREATMENT 记你的导演答案，SCRIPT 记台词**。这篇讲前两份怎么写、边界在哪。

## 一、BRIEF：只记用户权威信息

BRIEF 不替用户做创意决策，只固化"用户给定、不能擅改"的东西。它是后续所有创作的护栏。

### 必填字段（缺了会实质改变结果的，先问用户）

- **目标 / 交付物**：要一条成片还是分镜脚本？竖屏还是横屏？总时长？要不要源工程文件（剪映草稿）？
- **观众与平台**：给谁看、发哪个平台、什么账号定位（影响画幅、时长、节奏、语气）。
- **核心目标**：带货转化 / 涨粉 / 种草 / 品牌认知 / 知识科普 / 纯娱乐，一条片只设一个主目标。
- **必守事实（claims）**：产品名、功能、价格、数据、功效、资质、使用方法——凡是不能编的，逐条列清并注明来源（用户素材 / 已核实 / 待核实）。**没有来源的不写成事实**。
- **产品真相**：真实使用场景、真实差异点、能演示的动作；避免"好用、高级、智能"这类无法拍摄的空话。
- **CTA**：结尾要观众做什么（点链接 / 评论 / 关注 / 进店）。
- **语言**：口播语言、字幕语言、是否双语、口音要求。
- **改编范围**：换人 / 换脸 / 换产品 / 换行业 / 换语言 / 换场景 / 换时长，各保留什么、增删什么（这是克隆任务的核心，写细）。
- **私有身份资产**：用户的 AI 模特 / 数字人（如已建身份卡）、品牌色、Logo、固定话术、专属素材库位置。
- **硬约束**：时长、画幅、必须出现 / 禁止出现的元素、禁区、合规红线、是否接受真人脸。
- **额度与模型偏好**：是否接受当前平台的高额度/会员模型档、单批生成数量上限、是否要先出样片。
- **用户保留决策**：哪些点用户明确要自己拍板（选角、价格、最终 slogan），先标出来，不替他定。

### 提问纪律

- 一次问清"会改变方向"的问题，最多 2–3 个；常规选角、镜头、美术、提示词由你决定，不要把选择题甩给用户。
- 信息足够就用合理默认值（竖屏 9:16、默认模型档、按单条上限分段），并在 BRIEF 里注明这是默认、可改。
- 缺真实素材（产品图、肖像、数据）时，先输出方案并把该项标为"待素材/假设"，不阻塞流程；但进入生成前必须落实。

## 二、TREATMENT：你的导演创意答案

TREATMENT 回答"这条新片怎样才能成立"，在任何镜头、提示词之前写定。它是一个完整的创意答案，不是点子清单。

### 核心要素

1. **一句话前提（logline）**：谁、在什么处境、发生什么、观众为什么要看下去。
2. **吸引力来源**：参考片最抓人的那个东西是什么（某种幽默、视觉反差、信息结构、情绪、悬念），在新片里如何依然成立。
3. **Hook（前 3 秒）**：开场给观众的问题、异常结果、冲突或强动作；继续观看的理由。
4. **Reveal（推进）**：论证如何一步步展开，每个"原来如此/出乎意料"落在哪。
5. **Payoff（收束）**：高潮与回报，如何呼应开场。
6. **CTA**：承接 payoff 自然落到行动。
7. **节奏曲线**：快慢分布、停顿、跳剪点、留呼吸的位置。
8. **角色与表演**：谁在说、对谁说、他对话题的态度（热情吐槽 / 怀疑求证 / 认真科普），贯穿全片的气质。
9. **镜头与场景**：A-roll 主画面、需要的 B-roll、机位与构图、场景的社会属性与调色。
10. **各视觉系统清单**：A-roll（承载语义的表演）、B-roll（证据/空镜）、字幕（说的话）、花字 Typography（独立标题/标签/榜单）、MG/UI（动态图形）、特效、声音（人声/环境/音乐/音效）。每个系统要做什么、不需要哪些系统（明确删掉某些系统比堆料更重要）。
11. **身份锚点**：反复出现的人物/产品/场景用什么做统一视觉锚点。
12. **未决创意问题**：还没想清、需要在拆参考或试生成后定的点。

### 忠实改编的继承原则

用户说"照这条做，但把 X 换成 Y"时：

- **没明说要改的结构与关系，默认继承**：铺垫/兑现关系、笑点的位置、榜单状态的推进、各层的分工、画面变化与话语的呼应。
- 但继承的是**功能关系**，不是具体秒数或像素。新演员语速不同，秒数会变；新产品形态不同，演示形式可以换。
- 明说要改的（目标、人、产品、语言、时长、平台），在 TREATMENT 里重塑。

## 三、改归属（防止改错文件、越改越乱）

| 你要改的东西 | 改哪份 |
| --- | --- |
| 目标、卖点、事实、CTA、语言、换谁换什么、时长画幅 | BRIEF |
| 故事前提、Hook/收束、镜头、场景、表演、视觉系统、节奏 | TREATMENT |
| 台词、说话人、字幕分组、双文本、语义锚点 | SCRIPT |
| 某个镜头的提示词、构图、参考图、候选素材、镜头时长 | shots/ 生成输入 |
| 选错了已生成的文件、合成顺序 | 合成工程（不回改创意） |

创意文档随认知更新而改写，不是流水账。每个发现写进它的归属文件，TREATMENT 里不堆 BRIEF 事实，BRIEF 里不写镜头细节。

## 四、阶段产物检查

- BRIEF 完成：用户读完能确认"你没误解我要什么、守住了哪些事实"。
- TREATMENT 完成：你能口述完整的新片——开场怎么抓人、中间怎么证明、结尾怎么回收、每个画面系统在何时起作用，且每个改编对象的出现形态都已覆盖（见 03）。
- 这两份用户确认后，才进入 SCRIPT 与素材生产。
