# 04 · 脚本与语义时间

SCRIPT 是新片**台词的唯一权威**。它只写要说的话和语义结构，不写参考时间码、不写画面提示词、不写模型参数。画面与声音去 `shots/` 里做。

## 一、分段（Segment）：按"可表演段落"，不按画面切

- 一个 Segment 围绕一个**思想/表达/动作**分组，是一段可以连续表演的话。
- 一个 Segment 可以包含多个说话轮次、多个镜头、一次分屏；反过来，多个生成片段也可以复用同一张人物场景图。
- 分段依据：自然的语流停顿、话题转变、表演长度，而不是每个画面切一刀。
- 分镜（SH）是后续素材生产的事，SCRIPT 先不管镜头数。

## 二、角色（Role）

每段台词标注说话人：`【主持人】`、`【旁白】`、`【嘉宾A】`、`【路人B】`。双人/多人要明确每句话归谁，配音时一个角色对应一个音色。

## 三、双文本：显示 vs 发音

字幕显示什么、嘴里读什么，是两件事。需要区分时在台词里用 `显示∥发音`：

| 情况 | 写法 | 字幕显示 | 实际口播 |
| --- | --- | --- | --- |
| 字母缩写 | `API∥A P I` | API | A P I |
| 缩写读单词 | `SQL∥sequel` | SQL | sequel |
| 年份 | `今年〈2026∥二零二六〉年` | 今年2026年 | 今年二零二六年 |
| 价格 | `〈¥19.9∥十九块九〉` | ¥19.9 | 十九块九 |
| 只显示不读 | `〈本活动最终解释权归商家所有∥〉` | 显示该字 | 不读 |
| 只读不显示 | `〈∥再见的手势〉` | 无 | 读"再见" |

- 普通写法就正常读的，不必标注。中文夹英文品牌名，通常不需要注音，除非名字易读错。
- 同一名字在全片每一次出现都用同样的读法，保证多次配音一致。
- 不要用"请读成 XX"这种旁白指令，读法写进发音侧，表演语气写在镜头导演里。

## 四、字幕切换与语义锚点

- **字幕块（Cue）**：一次停留在屏幕上的话语块，不是一行字。用换行/`|` 表示一次刻意的切换。短句能给笑点留白，长句让解释呼吸——按"观众能不能边看画面边读完"决定。
- 一个意群要保持在一起：名字、否定词、数量+单位、介词+宾语、动词短语不要硬拆开（中文把复合词、定语和宾语放一起）。
- **语义区间（Selection）**：给一段"意思跨度"命名，供 B-roll/图形覆盖。如"演示覆盖整段解释"。
- **语义时刻（Moment）**：给一个"事件点"命名，供花字、音效、图形一起响应。如"答案揭晓""排名落定""价格出现"。
- 在脚本里用方括号标注，如 `【Moment:价格揭晓】`、`【Selection:使用演示 00:xx-00:xx】`，后期合成时把素材/音效挂到这些锚点上。

## 五、无台词段

没有台词不等于没有意义：

- 空段仍保留分段名与身份，如 `【空段·产品特写】`，时长由动作/音乐/视觉节奏决定。
- 纯图形动画、音乐卡点蒙太奇，用时间轴直接定位，不需要硬编台词。
- 说话段、无台词段、纯图形段可以共存在一条片里。

## 六、时长估算（先估算，再定生成条数）

**估算只用来决定要多少素材；生成后以实际配音/成片时长为准，不要拿估算当最终时间轴。**

口径（与适配层当前环境的视频生成规范一致，见 [00-tool-adapters.md](00-tool-adapters.md)）：

- 快节奏带货/信息流：每秒约 3–5 个汉字，硬上限 5 字/秒。
- 舒缓/品牌/抒情/讲解：每秒约 2–4 个汉字，硬上限 4 字/秒。
- 中文按**汉字数**（发音侧），英文按**音节数**；数字按发音侧读法算（"2026"读"二零二六"是 4 个音节）。
- 已包含正常句间停顿；需要反应/演示/留白时另加缓冲。
- 英文无官方密度时按正常语速约 3–4 音节/秒估，标注为估算。

估算流程：

1. 每段先按发音侧数字数/音节，除以语速，向上取整到秒。
2. 加表演反应、演示、留白的缓冲。
3. 对照适配层当前平台模型单条上限（见 00）。超了就把一个可表演段落拆成两段，或在自然的话题转折处拆分。
4. 不要为了塞满时长硬凑——能 6 秒讲完就别拖到 15 秒；只有新增证明、反应、升级才加时长。
5. 成片以配音/生成素材的实际时长为准，再据此对齐字幕和 B-roll。

## 七、把意思绑到时间锚点

- 凡是要让画面/图形/音效跟随的台词，先在脚本里命名 Selection/Moment。
- 图形揭示跟 Moment，B-roll 覆盖跟 Selection，新片里的位置由新台词决定，不抄参考秒数。
- 素材生成并验收后，再建立等长的实际时间窗；只有需要"逐字/逐词对齐"时才做精确对齐，纯背景 B-roll 不需要逐词对齐。

## 八、脚本格式（Markdown，见 templates/SCRIPT.md）

```
## S01 开场钩子（估时 ~6s）
【主持人】{你还在手动记每一笔开销？〈API∥A P I〉一个晚上就能帮你搞定。}
【Moment:抛问题】

## S02 演示（估时 ~9s）
【主持人】{你看，扫一下小票，〈¥19.9∥十九块九〉自动归类。}
【Selection:扫码演示，覆盖 B-roll 演示画面】
【空段·结果特写 ~1.5s】
```

台词用 `{}` 包住；双文本用 `〈显示∥发音〉`；锚点用方括号。每个生成片段可含多轮台词，不要把一句句切成独立视频。

## 九、完成标准

- 逐句可朗读，显示与发音分离清楚，名字/数字/价格读法统一。
- 每段估时在模型单条上限内，全片时长加总符合平台目标。
- 所有需要画面/音效跟随的点都标了 Selection/Moment。
- 用户提供的台词原文锁定，未授权不增删改；需要你起草时，台词完整写进 SCRIPT，不留"这里自由发挥"。
